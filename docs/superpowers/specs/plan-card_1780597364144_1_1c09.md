## Architecture Decisions

### 1. Deduplication strategy — `INSERT OR IGNORE`
Use `INSERT OR IGNORE INTO leads (...) VALUES (...)`. SQLite fires the `IGNORE` conflict resolution on the `UNIQUE` constraint of `google_id`, silently skipping duplicates. This is cheaper than `ON CONFLICT DO UPDATE` (no write amplification) and correct: a re-scraped lead that already exists should not overwrite existing curated data.

Alternative considered: `INSERT INTO ... ON CONFLICT(google_id) DO NOTHING` — functionally identical but less portable to older SQLite versions. `INSERT OR IGNORE` works on all SQLite 3.x. Prefer `INSERT OR IGNORE`.

### 2. Schema column order and types
Match the spec exactly:
```sql
id           INTEGER PRIMARY KEY   -- autoincrement implicit in SQLite
google_id    TEXT UNIQUE NOT NULL  -- Maps URL token, dedup key
name         TEXT
rating       REAL
reviews_count INTEGER
phone        TEXT
website      TEXT
address      TEXT
category     TEXT
scraped_at   TIMESTAMP             -- ISO-8601 string; stored as TEXT in SQLite
```
`scraped_at` uses `DEFAULT (datetime('now'))` so callers that omit it get a server-side timestamp.

### 3. Connection management
Each public function opens and closes its own connection. No module-level persistent connection (avoids stale connection under Streamlit's multi-thread reloader). Use context manager (`with sqlite3.connect(DB_PATH) as conn`) — auto-commits on success, auto-rolls back on exception.

### 4. `save_lead` parameter shape
Accepts a plain `dict` whose keys match column names (minus `id`). Unknown keys are ignored. Missing keys fall back to `None` (SQLite NULL). `scraped_at` defaults to `datetime.utcnow().isoformat()` if absent from the dict.

### 5. `fetch_all_leads_as_dataframe` uses `pd.read_sql_query`
Per spec. Passes the open `sqlite3.Connection` directly — pandas accepts `sqlite3.Connection` as the `con` argument without SQLAlchemy.

### 6. DB file path
Keep `DB_PATH = "data.db"` (existing value). Callers can override by monkey-patching or by passing an explicit path if we later add a `db_path` param — out of scope now.

### 7. Remove `get_connection` helper and `save_results` / `load_results` stubs
`get_connection` is replaced by inline context managers. `save_results` and `load_results` are replaced by `save_lead` and `fetch_all_leads_as_dataframe` respectively. `app.py` imports will need updating but that is out of scope for this card.

### Step 3 — `initialize_db()`
```python
def initialize_db() -> None:
    with sqlite3.connect(DB_PATH) as conn:
```

- No-op if table already exists.

### Step 4 — `save_lead(lead_dict)`

```python
_INSERT_SQL = """
INSERT OR IGNORE INTO leads
    (google_id, name, rating, reviews_count, phone, website, address, category, scraped_at)
VALUES
    (:google_id, :name, :rating, :reviews_count, :phone, :website, :address, :category, :scraped_at)
"""

def save_lead(lead_dict: dict) -> None:
    row = {
        "google_id":     lead_dict.get("google_id"),
        "name":          lead_dict.get("name"),
        "rating":        lead_dict.get("rating"),
        "reviews_count": lead_dict.get("reviews_count"),
        "phone":         lead_dict.get("phone"),
        "website":       lead_dict.get("website"),
        "address":       lead_dict.get("address"),
        "category":      lead_dict.get("category"),
        "scraped_at":    lead_dict.get("scraped_at", datetime.utcnow().isoformat()),
    }
    with sqlite3.connect(DB_PATH) as conn:
        conn.execute(_INSERT_SQL, row)
```

- Named parameter binding (`:key`) prevents SQL injection.
- `INSERT OR IGNORE` skips rows where `google_id` already exists.
- `scraped_at` defaults to UTC now if not supplied.
- `google_id=None` would violate `NOT NULL` — SQLite raises `IntegrityError`; caller is responsible for supplying a valid `google_id`.

---

### Step 5 — `fetch_all_leads_as_dataframe()`

```python
def fetch_all_leads_as_dataframe() -> pd.DataFrame:
    with sqlite3.connect(DB_PATH) as conn:
        return pd.read_sql_query("SELECT * FROM leads", conn)
```

- Returns empty DataFrame (0 rows, correct columns) if table is empty.
- `pd.read_sql_query` infers column names from cursor description.
- If table does not exist yet (before `initialize_db()` is called), SQLite raises `OperationalError`. Document this precondition.

- Each call opens and closes its own connection — safe under Streamlit's threaded reruns.
- `initialize_db()` must be called before any `save_lead` or `fetch_all_leads_as_dataframe` call.

## Risks and Edge Cases

| Risk | Mitigation |
|---|---|
| `save_lead` called before `initialize_db()` | `fetch_all_leads_as_dataframe` would raise `OperationalError: no such table`. Document precondition; optionally call `initialize_db()` at module import time (but that has side effects). |
| `google_id=None` in dict | SQLite raises `IntegrityError` (NOT NULL). Caller must validate before calling `save_lead`. |
| Concurrent writes from multiple Streamlit threads | SQLite WAL mode handles reads; writes serialize via SQLite's file-level lock. Low-volume scraper — acceptable. No connection pooling needed. |
| `reviews_count` as float from scraper (e.g. `"1,234"` parsed incorrectly) | Schema stores `INTEGER`; SQLite silently truncates floats. Caller must cast to `int` before passing. Document in `save_lead` docstring. |
| `scraped_at` timezone ambiguity | `datetime.utcnow().isoformat()` produces no `Z` suffix. Consistent within the system; document as UTC. |
| Large result sets from `fetch_all_leads_as_dataframe` | No pagination. For scraping runs >100k rows, caller should add a `WHERE` clause. Out of scope. |
| `DB_PATH` relative path resolves differently when called from different working dirs | Document that callers should `chdir` to project root or override `DB_PATH` with an absolute path. |
| Removing `get_connection`, `save_results`, `load_results` | `app.py` currently calls `database.load_results()`. `app.py` must be updated to call `database.fetch_all_leads_as_dataframe()` — flag this as a follow-up to avoid breaking the Streamlit app. |
