## Architecture Decisions

### Threading Model
`scrape_multi` is synchronous Playwright — calling it on Streamlit's main thread freezes the UI. A `threading.Thread` is started on button click; the thread writes `st.session_state.leads_collected` (int) and `st.session_state.scraping_active` (bool) at safe checkpoints. Streamlit's session state is safe to write from a non-main thread when no rerun is in progress, making a simple flag pattern viable.

### Auto-refresh for Real-time Metrics
Use `@st.fragment(run_every=2)` (Streamlit ≥1.37) on the status widget container. This re-executes only the fragment every 2 s, avoiding a full page rerun. The fragment reads `st.session_state.leads_collected` and `st.session_state.current_query` and renders `st.metric` cards. Fragment auto-refresh is only active while `st.session_state.scraping_active is True`; the `run_every` argument is set conditionally: `run_every=2 if st.session_state.scraping_active else None`.

### Speed Preset → Delay Constants
`scraper.scrape_multi` is extended with an optional `delay_preset: str = "normal"` parameter. The function maps this to `(inter_min, inter_max)` tuples before the loop, overriding the module-level constants locally (no global mutation):

```python
_SPEED_PRESETS = {
    "slow":   (15.0, 30.0),
    "normal": (5.0,  15.0),   # existing defaults
    "fast":   (1.5,   5.0),
}
```

### Lead Adapter (scraper → database)
`scraper.scrape_multi` returns dicts with keys `name, rating, reviews, phone, website`. `database.save_lead` expects `google_id, name, rating, reviews_count, phone, website, address, category`. The adapter lives in `app.py` as `_adapt_lead(record: dict) -> dict`:

```python
import hashlib

def _adapt_lead(record: dict) -> dict:
    key = f"{record.get('name', '')}|{record.get('phone', '')}"
    return {
        "google_id":     hashlib.md5(key.encode()).hexdigest(),
        "name":          record.get("name", ""),
        "rating":        record.get("rating", ""),
        "reviews_count": record.get("reviews", ""),
        "phone":         record.get("phone", ""),
        "website":       record.get("website", ""),
        "address":       "",
        "category":      "",
    }
```

### Export
`st.download_button` with `data=` set to an in-memory bytes buffer produced by `df.to_csv()` or `df.to_excel()` via `io.BytesIO`. No temp files. The `fetch_all_leads_as_dataframe()` call happens at button-click time so exports always reflect current DB state.

```python
# ---------------------------------------------------------------------------
# Background scraper thread
# ---------------------------------------------------------------------------

def _run_scrape(queries: list[str], preset: str) -> None:
    """Run in a background thread. Updates session state at checkpoints."""
    try:
        for i, query in enumerate(queries):
            st.session_state.current_query = query
            batch = scraper.scrape_multi([query], delay_preset=preset)
            for record in batch:
                database.save_lead(_adapt_lead(record))
                st.session_state.leads_collected += 1
    except Exception as exc:  # noqa: BLE001
        st.session_state.scrape_error = str(exc)
    finally:
        st.session_state.scraping_active = False
        st.session_state.current_query = "—"


# ---------------------------------------------------------------------------
# Start Scraping button
# ---------------------------------------------------------------------------

parsed_queries = [q.strip() for q in queries_raw.splitlines() if q.strip()]

with st.container(horizontal=True):
    start_disabled = st.session_state.scraping_active or not parsed_queries
    if st.button(
        ":material/play_arrow: Start Scraping",
        type="primary",
        disabled=start_disabled,
        help="Disabled when no queries entered or scrape already running.",
    ):
        preset = _SPEED_MAP.get(speed_label, "normal")
        st.session_state.scraping_active = True
        st.session_state.leads_collected = 0
        st.session_state.scrape_error = None
        t = threading.Thread(
            target=_run_scrape,
            args=(parsed_queries, preset),
            daemon=True,
        )
        t.start()
        st.rerun()
```

## State Management Strategy

All mutable UI state lives in `st.session_state`. Initialised at module top-level with `setdefault` so re-runs never reset values.

| Key | Type | Purpose |
|-----|------|---------|
| `scraping_active` | bool | Guards start button; drives fragment refresh rate |
| `leads_collected` | int | Per-session counter incremented by background thread |
| `current_query` | str | Displayed in status caption during active scrape |
| `scrape_error` | str or None | Surfaces background thread exceptions in UI |
| `queries_input` | str | Bound to sidebar text_area via widget key |
| `speed_select` | str | Bound to sidebar selectbox via widget key |

The background thread writes to session state directly. This is safe in Streamlit because the GIL ensures atomic writes to Python objects, and the thread only increments integers and assigns strings (no compound read-modify-write on shared collections).

## Accessibility Considerations

1. **Labels on every widget** — all `st.text_area`, `st.selectbox`, `st.button` have descriptive labels and `help` text.
2. **Material Symbols icons** via `:material/icon_name:` syntax — purely decorative; screen readers skip them.
3. **Metric cards** use `st.metric` with explicit `label` strings — screen readers announce label + value.
4. **Error messages** use `st.error()` — rendered in a landmark region with appropriate ARIA roles by Streamlit.
5. **Empty state** uses `st.info()` with instruction text so the page is not blank.
6. **Download buttons** have distinct, descriptive labels (not just "Download") so screen readers disambiguate.
7. **Disabled state** on Start Scraping button carries `help=` text explaining why it is disabled.

## Risks and Edge Cases

| Risk | Mitigation |
|------|------------|
| Background thread raises unhandled exception | `try/finally` in `_run_scrape` catches all exceptions, sets `scrape_error`, always clears `scraping_active` |
| `scrape_multi` called with single query per iteration — doubles inter-query delay timing | Thread calls `scraper.scrape_multi([query])` one query at a time, so the single-query fast-path (no inter-query sleep) is used per iteration. The per-query delay is in `_collect_nodes` (profile delay), not the inter-query constant. For multi-query dedup logic, the thread's own `save_lead` deduplication via `google_id` suffices. |
| `google_id` collision — two different businesses with same name + same phone | Extremely unlikely in practice; `INSERT OR IGNORE` silently deduplicates. |
| `openpyxl` not installed | Added to `requirements.txt` in Task 1; `_df_to_excel_bytes` will fail fast at import if missing. |
| Empty DB on export → no file | Guard `if _export_df.empty` replaces buttons with a caption. |
| `@st.fragment` `run_every` deprecated in future Streamlit | Flag is conditional (`None` when idle), so even if removed it degrades gracefully to static rendering. |
| User enters queries with trailing whitespace | `q.strip()` in `parsed_queries` comprehension normalises input. |
| `st.session_state.scraping_active` is `True` after server restart | Lost on restart — `setdefault("scraping_active", False)` at module top ensures clean state. |
| `use_container_width` — deprecated in current Streamlit | Never used in this plan; `width` param omitted (stretch is default). |
